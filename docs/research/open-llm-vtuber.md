# Open-LLM-VTuber Architecture, Features, & Failure Analysis

> **Notice:** This document is produced under clean-room research guidelines. Mechanisms are analyzed conceptually and described in original prose. No source code, prompt templates, or assets were copied.

---

### 1. Repository Overview & Architecture Summary

**Open-LLM-VTuber** is an open-source, voice-interactive virtual companion framework designed to connect LLM reasoning agents with real-time Speech-to-Text (ASR), Text-to-Speech (TTS), Voice Activity Detection (VAD), and Live2D animated avatars over WebSocket connections.

```
+-----------------------------------------------------------------------------------+
|                                 FRONTEND (Web Client)                             |
|  - Live2D Cubism Render Canvas   - Audio Worklet / WebAudio Playback Engine       |
|  - Expression & Motion Controllers - Mic Audio Streamer & Interruption Handler    |
+-----------------------------------------------------------------------------------+
                                         ^ | (WebSocket /ws)
                                         | v
+-----------------------------------------------------------------------------------+
|                             BACKEND SERVER (FastAPI / WebSockets)                 |
|  [websocket_handler.py]                                                           |
|    - Audio Chunk Ingestion & VAD Triggering (Silero VAD)                         |
|    - Interruption Interrupt Frame Dispatcher                                      |
|                                                                                   |
|  [conversation_handler.py & single_conversation.py]                               |
|    - Streaming LLM Sentence Divider (sentence_divider.py)                        |
|    - Async Pipeline Orchestration                                                 |
|                                                                                   |
|  [mcpp / MCP Client]                    [asr & tts Modules]                       |
|    - FastMCP Tool Integrations            - Multi-provider ASR (Whisper, Groq)    |
|    - Tool Guidance Prompt Adapters        - Multi-provider TTS (Edge, Cartesia)   |
+-----------------------------------------------------------------------------------+
```

#### Core Mechanical Architecture
- **Transport Layer (`src/open_llm_vtuber/server.py`, `websocket_handler.py`):** Uses FastAPI WebSocket endpoints to stream binary PCM microphone audio from the browser and send back synthesized TTS audio chunks alongside JSON payload control messages (emotions, motion triggers, subtitle text).
- **VAD & Audio Segmentation (`src/open_llm_vtuber/vad/silero.py`):** Evaluates incoming audio buffers using Silero VAD. Upon detecting speech boundaries, it triggers ASR transcription.
- **ASR Subsystem (`src/open_llm_vtuber/asr/`):** Supports local Whisper (`faster_whisper_asr.py`, `whisper_cpp_asr.py`, `sherpa_onnx_asr.py`) and cloud ASR (`groq_whisper_asr.py`, `azure_asr.py`, `openai_whisper_asr.py`).
- **Streaming Sentence Division (`src/open_llm_vtuber/utils/sentence_divider.py`):** Tokens generated by the LLM are buffered into sentence fragments using punctuation delimiters. As soon as a complete sentence is parsed, it is immediately dispatched to the TTS pipeline while the LLM continues generating subsequent text.
- **TTS & Audio Queue Manager (`src/open_llm_vtuber/conversations/tts_manager.py`):** Asynchronously synthesizes sentences into audio bytes (`edge_tts.py`, `cartesia_tts.py`, `openai_tts.py`, `piper_tts.py`, `gpt_sovits_tts.py`) and streams them back to the client.
- **Live2D Emotion & Motion Mapping (`src/open_llm_vtuber/agent/transformers.py`, `config_manager/character.py`):** Parses emotion tags (e.g. `[happy]`, `[blush]`) embedded in persona prompts or generated by the LLM, mapping them to Live2D model expression indexes.
- **MCP Tool Protocol Integration (`src/open_llm_vtuber/mcpp/`):** Implements an Model Context Protocol (MCP) client (`mcp_client.py`) that connects to external tools, maps tool schemas into OpenAI function-calling formats, and injects tool results back into the conversation context.

### 2. Feature Mechanics & Implementation Analysis

#### A. Voice Interruption & Barge-in Handling
- **Mechanism (`src/open_llm_vtuber/websocket_handler.py`):** While the assistant is speaking (TTS active and streaming audio), the microphone remains open. If Silero VAD detects user speech (`speech_start`), `websocket_handler.py` immediately cancels the active LLM asyncio task, cancels pending TTS generation jobs in `tts_manager.py`, and sends a control frame (`{"type": "control", "text": "interrupt"}`) to the client.
- **Client Response:** The browser audio queue is cleared instantly to halt speaker output.

#### B. Streaming Sentence-Level Low Latency Pipeline
- **Mechanism (`src/open_llm_vtuber/utils/sentence_divider.py`):** Rather than waiting for complete LLM responses (which causes 2–5s delays), the output generator passes tokens through a regex punctuation matcher. Once a sentence terminator (`.`, `!`, `?`, `\n`, `。`, `！`, `？`) is encountered, the text segment is yielded immediately to TTS.

#### C. Persona & Multi-Character Switching
- **Mechanism (`src/open_llm_vtuber/config_manager/character.py`):** Characters are stored as YAML configurations defining system prompts, TTS voice configurations, Live2D model paths, and default emotion parameters. Users can switch active personas without restarting the server.

#### D. Model Context Protocol (MCP) Integration
- **Mechanism (`src/open_llm_vtuber/mcpp/mcp_client.py`, `tool_manager.py`):** Connects to MCP servers via stdio or SSE transports. Automatically extracts JSON schemas of registered tools and injects system instructions (`tool_guidance_prompt`) directing the LLM when and how to invoke tools.

### 3. Failure Modes, Real-World Bugs, & Flaws

Based on code analysis and commit logs (e.g. commits `fccb29b`, `8e81732`, `6784c17`, `b62a30f`):

1. **Empty LLM Chunk Crash (`commit fccb29b`):**
   - *Flaw:* When upstream cloud providers (e.g., OpenAI, Groq) return empty stream chunks or stop reasons without delta content, the response parser attempted to index into empty arrays, triggering unhandled `IndexError: list index out of range` exceptions that killed the WebSocket connection.
2. **MCP Tool Loop Deadlocks & Memory Leaks (`commits 8e81732, 6784c17, e1efbec`):**
   - *Flaw:* Recursive tool calls lacked maximum execution depth guards. If a tool output triggered another tool call in an infinite loop, the session context grew indefinitely until Python ran out of memory. Stdio subprocesses for MCP servers were not cleanly terminated on client disconnect, resulting in orphaned background processes.
3. **TTS Buffer Underflow & Audio Stutter (`commit b62a30f`):**
   - *Flaw:* Streaming short sentence fragments to cloud TTS providers with high connection overhead caused audible gaps between sentences. If a provider returned unsupported audio sample rates, playback failed silently.
4. **VAD False Positive Interruption Spam (`src/open_llm_vtuber/vad/silero.py`):**
   - *Flaw:* Background noise or user coughs triggered VAD speech detection, prematurely cancelling long LLM reasoning responses before completion.
5. **Zero Security Isolation & Unsanitized Tool Prompts (`src/open_llm_vtuber/mcpp/tool_executor.py`):**
   - *Flaw:* MCP tools execute with full privileges of the host process. There is no approval modal, human-in-the-loop confirmation, or command allowlist. Prompt injection from external web pages or tool outputs can execute arbitrary commands on the user's host machine.

---

### 4. Key Lessons & Architectural Guidance for NIKO

1. **Sentence-Level Streaming for Audio:** Adopt sentence-boundary buffering (`sentence_divider`) for NIKO's future TTS pipeline to ensure sub-500ms Time-To-First-Audio (TTFA).
2. **Robust Empty Chunk Defense:** Ensure NIKO's streaming parser strictly guards against null/empty LLM deltas across all providers.
3. **Strict MCP Tool Scoping:** Unlike Open-LLM-VTuber's unmonitored MCP execution, NIKO's human-in-the-loop approval gate (`ApprovalService`) and provenance tracker MUST filter all MCP tool invocations.
4. **Resilient Process Lifecycle:** All subprocesses and worker tasks must be registered with clean cancellation handlers tied to FastAPI's lifespan and WebSocket connection state.
